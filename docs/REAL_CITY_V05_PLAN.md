# 霓港 · 真实城市制作与验收计划

编制日期：2026-09-29。起点是已发布的 v0.4.0（`5266fae`）。本计划回应港湾天际线、空房间与无法上楼、地铁入口跳转、积木感和整体完成度五项反馈。最终目标是能步行理解、进入并使用的城市；v0.5 是实现该目标的下一批产品内容，不以版本号、楼栋数或测试数宣称达到商业 3A 制作水准。

## 1. 已确认的体验问题

审阅了当前源码、v0.4 实际线上截图以及 v0.4 近景截图。以下判断来自产品画面和通行实现，不把策划文案当成功能证据。

| 用户所见 | v0.4 证据与原因 | 必须改变的产品体验 |
| --- | --- | --- |
| 没有壮观的维港式景观 | 普通开始位置仍在南岸 `(8,174)`，主菜单和开始画面是宽十字路；北岸地址藏在导览后。既有海峡宽约 114 米，密集高层集中在单排金融区 | 主入口直接到真实可走的海滨；近景岸线、中景渡轮和连续高低塔群形成宽幅港湾画面，昼夜都成立 |
| 房子空、不能上楼 | 每栋只有大厅、远隔的主题层、观景层；主题层常在数十米高处。长中轴和四分区复用使正常入口视角仍空 | 从入口看见家具与用途，能沿实体楼梯到连续二、三层；电梯保留真实升降与高层观景 |
| 地铁不像实际车站 | 站外按 E 将角色直接切至 -14 米站台；站厅、楼梯和闸机不构成可走的连续路线 | 街口 → 梯段 → 平台 → 站厅 → 闸机通道 → 站台，每步有实体支撑、扶手、层高和导向 |
| 总体像积木演示 | 南岸重复盒子立面、大片道路、块状树冠和人偶；材质虽有贴图，轮廓、灯光及尺度仍过于均质 | 优先改变主画面的轮廓、密度、材质响应与灯光，再制作有辨识度的入口、室内和人物动作 |
| 数量增加但品质变化不明显 | 48 地址、144 公共层通过规则不等于全址艺术验收；用户不会主动复现测试路线 | 以普通玩家第一次进入的画面与完整通行路线作为验收主线，统计仅用于检查漏项 |

南岸背景楼目前不在 48 个可进入北岸地址内。新制作必须清楚标识开放入口，后续按南岸街段逐栋替换；不能把新增远景塔群算作新增可进入建筑。

## 2. 制作顺序与阶段完成门槛

| 阶段 | 制作单元 | 完成门槛 | 未达到门槛时的处理 |
| --- | --- | --- | --- |
| A · 第一眼 | 主菜单取景、海滨开始入口、旧存档导览、步行视角 | 默认高画质正常开始即可看见港湾；无需开发指令或记住北岸坐标；旧存档能通过清楚的产品入口抵达 | 修入口和构图，不用演示视频替代可玩的现场 |
| B · 港湾整体 | 岸线、前景步道、中景船舶、连续天际线、远山、海面、昼夜灯光 | 三个实际可抵达视点都具有前中远景；地标有不同轮廓；水面没有重叠闪烁；船只沿真实航线行驶 | 调整城市布置、轮廓及材质，不能只继续增加同形塔块 |
| C · 交通连续 | 全部地铁站，以及后续轻轨、高铁、渡轮地面衔接 | 从街面逐段走至候车点再返回；中途高度连续；真实候车、上车、行驶、下车不被入口重做破坏 | 保留失败路径坐标与截图，先修几何、支撑及碰撞 |
| D · 可生活楼层 | 北岸 48 地址连续低层、楼梯、电梯和家具；先打磨样板 | 一栋完整路线通过后再扩展同类；连续低层没有悬空、穿板、错层吸附或空白着陆层 | 未通过的地址保留待验收状态；不能用数据生成成功结束制作 |
| E · 逐栋艺术生产 | 48 张建筑卡，逐公共楼层及房间拍摄；南岸另建地址卡 | 每址立面、街角、入口、楼梯、房间、顶层视景都有可审画面；同业态的空间关系和辨识物有差异 | 回到具体房间/立面修订，不做最后统一换色的批量“完成” |
| F · 城市行为 | 居民跨街、出入、候车和上下班，车辆路权，服务点及日常玩法 | 行为有真实目的地；行人车流不会永久阻塞；NPC 能完成可观察的日常链路 | 按街区、小规模运行，达到稳定后扩展人口 |
| G · 发布与性能 | 默认高质量、按需加载、资源释放、输入与存档、实机测量 | 功能、视觉、资源三类证据分别通过；发布产物与测试修订相同；线上核心路线成立 | 不暗降默认画质、不提高等待预算掩盖卡顿，不把软件渲染帧率当硬件成绩 |

v0.5 的制作重点为 A–D，以及 E 的港湾和代表建筑样板。E 的全址手工复核、南岸逐栋室内、所有自然楼层、F 的完整城市行为和 G 的实机性能是长期目标，逐项推进，未验收不写完成。

## 3. 第一条核心游玩路线

先确保一条路线足够清楚、完整、值得走，再把成立的空间方法扩展到全城。

1. 在主菜单选择海港漫步。角色落在实际步道上，以人眼高度看见水面、渡轮、连续高楼和可辨认塔冠。
2. 沿栏杆走到下一个观察点。路面、坐凳、灯柱、树池有真实尺度，栏杆缺口仅对应入口或台阶。
3. 通过可见导向抵达车站街口，沿实体楼梯走下；在中段能回头看到上层街光，抵达站厅后看到正确的线路、出口与候车方向。
4. 实际走到站台，等一班列车，上车，行驶，在另一站下车；沿楼梯回到地面。目录快速旅行不作为这段路线的替代证据。
5. 从街道进入一个有明确门面和业态的样板建筑。大厅第一眼看见服务台、展品或生活空间，而非长空走廊。
6. 走楼梯到二层，穿过真实门洞，接近关键家具；再走至三层的另一种用途空间。测试记录梯中高度，证明不是切层跳转。
7. 走进电梯，选择公共顶层。轿厢连续升高，到层后走出，看见港湾或山城；回到大厅并离开建筑。
8. 保存并重开。恢复在安全可达的位置，建筑、交通、人物和相机状态不残留错误。

每次制作收尾都复核这条路线的入口可发现性。导览可作为远距离出行便利，但实际楼梯、站台和室内最后一段必须由角色自己走通。

## 4. 港湾与地标制作卡

| 单元 | 制作内容 | 画面验收 |
| --- | --- | --- |
| 海滨前景 | 连续步道、海堤厚度、金属扶手、石材接缝、坐凳、导向、近岸水线 | 人眼高度可读真实尺寸，边缘没有重复盒块及穿插，镜头能靠近而不越堤 |
| 跨海中景 | 既有渡轮真实运行、码头入口、航行水面、桥梁和交通关系 | 船舶不是背景贴片，靠泊位置与上下客一致；码头与岸线连接清楚 |
| 高楼群 | 不同高度的塔身、收分与退台；独立冠部、裙楼与结构节奏 | 至少三种主轮廓；塔群疏密有节奏，临海低层不能把全部塔身挡住 |
| 远景层 | 更密的中高层与远山、薄雾和天空亮度 | 远近有层次；不能把整座城变成同一饱和度的灰蓝块 |
| 海面 | 波纹方向、反射强度、岸边过渡与夜间灯影 | 海水有尺度且不过度金属化；远处不产生明暗网格，静态截图和行走中都检查 |
| 日夜 | 白昼表面辨识、黄昏轮廓、夜晚窗灯与街灯 | 夜景保留暗部与主次，不把所有窗同时点亮；白天不能依靠霓虹掩盖造型不足 |
| 远景与近景加载 | 永久保留低成本轮廓；靠近后加载窗、阳台、入口与材质 | 走近地标时不会整栋突然消失；可进入与背景楼分开记账，加载范围及预算有记录 |

新增轮廓必须在真实相机位置复核。城市总平面、模型预览和生成素材可辅助制作，但不作为游戏画面的验收截图。

## 5. 每栋建筑和每个楼层的制作标准

每栋地址固定一张制作卡，记录开放楼层的真实 ID、高度、入口和用途。v0.5 连续低层的目标为大厅 0 米、二层 4.2 米、三层 8.4 米，并保留原公共顶层；这四个公共层不能写成整栋所有自然楼层。

| 制作卡字段 | 需要填写与检查的内容 |
| --- | --- |
| 街道与入口 | 地址、门牌、入口坐标、主立面、落客/步行关系、白天和夜晚入口画面 |
| 低层布局 | 0/4.2/8.4 米的实际楼梯通路；主通道、房门、电梯之间清楚连续；楼梯下空间和顶层开洞真实 |
| 房间 | 用途、尺寸、主要家具、活动点、储物、采光、灯具、入口和出口；家具摆法应解释使用者如何生活或工作 |
| 材质 | 每址主材、辅材和金属/玻璃/织物区别；有材质来源和真实尺寸，不以随机脏污代替设计 |
| 使用痕迹 | 只在合理位置出现的书刊、收纳、货物、菜单、磨损或修补；不能所有房间重复同一盆栽组合 |
| 垂直交通 | 两段低层楼梯双向通行；每层有可读层号和电梯口；高层电梯到达后可走出、返回 |
| 观景 | 真实可见的港湾、街区或山景；栏杆、窗和建筑壳不封住视线；视点可由普通操作抵达 |
| 状态 | 设计 / 已制作 / 几何通过 / 浏览器路线通过 / 代表画面通过 / 全址画面通过；证据链接与修订分别记录 |

最小完整路线为“街道 → 入口 → 大厅 → 楼梯 → 二层房间 → 楼梯 → 三层房间 → 电梯 → 顶层观景 → 电梯或楼梯返回 → 街道”。文化、住宅、医疗、餐饮、商务至少各一个样板完整复核，再逐址扩展。

## 7. 消除积木感的实际制作方法

- **轮廓先行**：高楼要有基座、塔身、收分和冠部；低层要有雨棚、门洞厚度、凹窗和转角。主轮廓用真实网格完成，不能只给盒子换贴图。
- **控制尺度**：在人眼高度比较门、栏杆、椅子、床、桌和人。公共大厅可以大，但须由活动、展品、排队、采光或结构解释空间；住宅和诊室按具体生活关系围合。
- **减少统一光泽**：石材、粉墙、织物、木、玻璃和金属使用不同粗糙度和细节；曝光、天空、环境反射与阴影一起调，不能用强泛光洗平细节。
- **材质和光照解耦**：日夜共用合理的材质基色；暗处仍有结构，窗灯和反射保持层次。近景细节须在平光和侧光两种条件下可读。
- **近景有使用关系**：先放桌椅、操作面和通路，再放书、器皿、工具与储物。道具种类服务于房间用途，数量不作为目标。
- **人物需独立制作**：现有人偶和活动标签不能代替骨骼、步态、转身、坐下与交互动作。后续分角色原型建立动作库，在真实尺度空间里审查。

参考 `https://github.com/brunosimon/folio-2025` 的可借鉴方向是统一美术语言、几何与材质完成度、光照构图、镜头和交互反馈。本轮已通过 GitHub 插件核对的具体源码与授权情况见 [REFERENCE_ART_DIRECTION_V05.md](REFERENCE_ART_DIRECTION_V05.md)。不能推定可复制全部模型、贴图、人物、字体或品牌内容，霓港保留自己的城市与资产设计。
