| 测试 | 已验证行为 |
| --- | --- |
| 1. 真实住址、店铺与路线 | 20 名独立居民，稳定身份；住宅实际包含卧室；住宅至三家店铺、货栈和仓库均有不穿建筑与家具的步行路径；门口至卧室的实际通路可达；货栈取货柜台不遮住住宅真实入口。 |
| 2. 有限货物配送 | 玩家必须在货栈附近领货、在收货柜台附近交货；领货扣货栈库存、支付批发款并留出运费；交货增加店铺库存，运费只付一次；在途货物可以存档恢复。 |
| 3. 居民真实采购 | 店员到岗、店铺有货且居民有钱时才成交；扣居民资金、加店铺资金、减现货；同一居民的同一商品一天只买一次；缺货或没钱不会成交。 |
| 4. 完整日程 | 工作、采购、配送、回家均由模拟推进。一个完整模拟日中 20 人都实际回到住宅休息，至少 15 人到岗，三家店铺均发生真实交易；视点远离街区或处于其他建筑内不停止生活。 |
| 5. 确定性恢复 | 相同种子和累计时间得到一致状态；一次推进与分帧推进一致；保存后继续与恢复后继续得到一致结果，工资时段不会重复结算。 |
| 6. 损坏存档与重置 | 不兼容版本、种子、凭空增加钱或货、跨商品篡改、非法位置、孤立配送单均被拒绝；重置原位清空生活进度，保留渲染器所持对象引用。 |
| 7. 真实电车通勤 | 至少 3 名居民乘坐实际车队并下车；上、下车走真实车门路径，测试中的每次平面步进小于 0.2 米。 |
| 8. 渲染预算与隔离 | 近景人物实例最多 12 个；远处释放实例；渲染器只读取状态，传入长时间也不会推进经济或日程。 |
| 9. 在车上存档 | 先恢复车队票据，再恢复居民在车上的路径与状态；继续推进与未中断模拟一致。 |
| 10. 调整显示时间 | 把显示时钟前后拖动不会重复支付已结算的工资时段，不会改变货币供给。 |
| 11. 玩家在柜台购物 | 测试等待店员按日程实际走到柜台；E 提示显示商品单价；一份商品实际扣库存、加随身物品，返回唯一的钱包扣款；恢复后重放同一请求不会再次扣款。 |
| 12. 购物失败与账目校验 | 远程购买、店员未到、资金不足或非法、闭店、售罄均不扣玩家资金；伪造支出、重复购买请求、没有真实交货依据的运费记录被拒绝。 |
| 13. 交通时钟 | 路口通行读取共享的运行时交通时钟；红灯等待、绿灯行走；该时钟不会覆盖存档中的经济日、工资时段。 |
| 14. 世界中的 E 购物与恢复 | 通过 `world.step` 等待店员到岗，通过世界交互购物，验证唯一玩家钱包 `sim.cash` 与真实库存同步减少；`safeSave` / `bind` 恢复后，已付款物品与支出账目仍在。 |

**可核验的初始数值。** 默认种子为 `749213`。居民总资金 `$1292`，货栈 `$900`，三家店铺各 `$260`、合计 `$780`，初始账目总额为 **$2972**。三种商品分别是果蔬、茶饮与热汤面；货栈每种 **96 份**，对应店铺各有 **4 份**，所以每种商品总量 **100 份**，合计 **300 份**。没有自动补货或凭空生产：货栈耗尽后，无法再发出有货保障的配送单；雇主没有钱时，无法支付工资。

三家交易店铺绑定实际建筑：`south-095` 潮叶果铺、`south-092` 静潮茶室、`south-090` 双碗面家。货栈位于 `south-089`，仓储岗位位于 `south-086`。这些 20 人有独立居民 ID；北岸现有居民不被批量替换成这套经济日程。

`south-089` 的真实门口仍为 `(187, 119.97975447401404)`；取货点位于门侧 `(193.5, 119.97975447401404)`，地面高 `0.18` 米，相距 `6.5` 米，超过建筑入口提示范围 `5.4` 米。以玩家默认碰撞半径 `0.65` 米沿门口至取货点每 `0.1` 米检查，共 66 个位置，没有静态实体阻挡；货箱位于取货点侧后方，不在这条通路上。

**现金与货物按实际转移核算。** 居民采购把钱转给店铺；店铺领货款转给货栈，运费进入托管；完成交货才把托管运费转给搬运居民或游戏钱包。每单最多 8 份，运费 `$12`。在岗居民每个已到达的经济小时时段可领 `$3`，同一时段不会重复支付。

玩家唯一可花的钱仍是 `sim.cash`。生活模块只记已经付给玩家的运费、玩家已经付给店铺的购物款，以及随身物品，不复制一个可花的钱包。购物必须满足实际柜台距离、营业时间、店员在岗、有限现货和足够资金；成功返回负 `cashDelta`，由世界接入扣款。购买请求 ID 持久化，已成功处理的请求不能重放成第二次扣款。

两个守恒关系由测试及恢复校验共同检查：

```text
店铺 + 货栈 + 居民 + 运费托管的现有钱
  + 已付给玩家的运费 - 玩家已付的购物款 = 初始 $2972

每种商品的货栈现货 + 店铺现货 + 在途货物
  + 玩家随身物品 + 居民累计已消费 = 初始 100 份
```

这里的货物总量是守恒计数，包含已消费份数；它不表示始终还有 300 份可出售。玩家买到的物品目前保留在随身库存，没有饮食消耗或属性恢复操作。

**一天的独立复核。** 从 06:00 开始，按每步 0.1 秒推进 840 秒，即默认 35 秒/小时的一整天。该复核直接运行生活模块，未连接共享车队；电车乘坐另由第 7、9 项测试验证。视点与室内参数故意指向远处，以验证生活不依赖可见街区。

```sh
node --input-type=module <<'JS'
import * as THREE from './vendor/three/three.module.js';
import { createCityExploration } from './src/city-exploration.js';
import { createHarborLife } from './src/harbor-life.js';
const city = createCityExploration(THREE, new THREE.Scene(), { streaming: false });
const life = createHarborLife({
  buildings: city.buildings, colliders: city.colliders, hour: 6,
});
for (let tick = 0; tick < 8400; tick++) {
  life.update(.1, {
    position: { x: 1400, z: -1000 }, interior: { buildingId: 'apex-tower' },
  });
}
console.log(JSON.stringify({
  seed: life.seed, time: life.time, day: life.day, hour: life.hour,
  money: life.totalMoney, goods: life.totalGoods,
  statistics: life.statistics, consumed: life.consumedByProduct,
  shops: life.shops.map(({ id, stock, sold, received }) => ({ id, stock, sold, received })),
  snapshotBytes: Buffer.byteLength(JSON.stringify(life.snapshot())),
}, null, 2));
JS
```

本次复核输出为：模拟时间 **840 秒**、第 **1** 天 **06:00**；现金守恒计数 **2972**，商品守恒计数 **300**；完成 **26** 次居民购买、**100** 次工资结算、**4** 次配送，另有 **22** 次未完成的时段采购。果蔬消费 **12** 份、茶饮 **4** 份、热汤面 **10** 份。尚未消费的货物合计 **274** 份。三家店铺的 `stock/sold/received` 分别为果铺 `0/12/8`、茶室 `8/4/8`、面家 `10/10/16`。该时刻的生活存档为 **35,015 字节**；这是这一具体状态的体积，不是所有存档的上限。不同起始时间、交通等待或玩家购物会改变经营结果，不能把这组交易数当成固定生成的 UI 数字。

**保存范围。** `neon-harbor/daily-life`、版本 `1` 保存种子、经济时钟、居民日程与路径、已结算工资和当日采购标记、钱与货、在途配送、玩家随身物品及购买去重记录；交易日志保留最近 96 条。车队另存运行时间、车辆状态与居民票据。恢复顺序为先重置旧生活、恢复车队，再恢复居民生活。暂停菜单或隐藏页面时游戏停止推进；关闭浏览器期间不计算离线生产。

**多人边界。** 新生活状态仍由各客户端独立模拟及本地保存。现有 [多人服务器快照](../../../tools/multiplayer-server.mjs)包含玩家位置、车辆、房间时钟与聊天，不包含港湾居民日程、车队居民票据、店铺库存、采购、配送托管或玩家随身物品。联机时可以同步既有房间位置和车辆体验，但这些新状态尚未由多人服务器统一权威核算；不能据此宣称不同玩家共享同一份库存、交易账或已验证跨客户端的防重复付款。上述 14 项结果验证本地模拟与世界接入，不构成多人经济一致性验收。
