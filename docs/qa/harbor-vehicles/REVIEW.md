夜景不只是把窗户涂亮：只读核对车辆源文件可见，两层客舱各有真正的暖色 `PointLight`，近层级时启用，且不投射阴影；灯条、路线牌和航行灯同时使用发光材质。截图中的局部亮度与反光可以观察，但不能据此推断真实城市街灯下的曝光、乘客面部照明、前灯照射效果或动态阴影质量。

上层图展示了明确的空间组织，也暴露了当前风格：座椅、扶杆、灯带和窗框采用少量重复构件，玻璃没有丰富的环境反射，宽阔顶面与地面较干净，物件缺少使用痕迹。下一步有价值的美术工作是加强座椅缝线与磨损、地板边界及窗框细节、外部五金和灯具的材质差异，并在实际城市昼夜环境中校准玻璃反射和照明。增加模型数量或三角面数本身不能证明这些差距已经解决。

## 证据范围与采集条件

原采集器以 `doorsOpen: true` 创建模型，并调用 `setDetail(0)` 强制展示最近层级。车辆单独放在地面/水面平面上，截图分辨率为 800×500、像素比为 1，使用 ACES 色调映射、独立半球光和方向光，以及 1024×1024 的 PCFSoft 方向光阴影。日景曝光为 1.1，夜景曝光为 0.9。上层图使用预设相机，不能代替真实玩家身高、碰撞和通行验证。

原始元数据的 `renderer: "WebKit WebGL"` 是 WebGL 的通用 renderer 字符串，不能据此认定采集浏览器为 Safari。采集代码实际通过 Playwright 启动 Chromium，要求 ANGLE SwiftShader。`errors: []` 对应原采集器监听的 `pageerror`；它没有记录全面的控制台、网络或 GPU 检查，也没有浏览器版本与硬件帧率记录。

## 可重现采集

已保存路径适配后的 [capture-vehicles.cjs](capture-vehicles.cjs)。它相对自身位置寻找项目根目录，通过项目依赖加载 Playwright，不依赖原工作区或绝对临时输出路径。默认输出为本目录下的 `recaptured/`，保留本次审查的九张原图。

```sh
node docs/qa/harbor-vehicles/capture-vehicles.cjs
```

可用第一个参数指定输出目录；可用 `CHROMIUM_PATH` 指定浏览器。未指定时优先采用存在的系统 Chromium，否则使用 Playwright 管理的 Chromium。新采集元数据额外记录浏览器版本、viewport、强制细节层级和独立夹具条件。重新采集使用当前车辆源文件，因此源文件、浏览器或图形后端改变后不承诺与这九张原图像素一致。

已实际运行路径适配后的工具完成九张重采。浏览器版本为 `151.0.7922.173`，`pageerror` 记录为空，九组场景指标与原始记录一致，九张重采 PNG 与原图逐字节一致。详见 [reproduction-check.json](reproduction-check.json)。这是同一项目、同一已安装浏览器和渲染环境中的重现校验。
