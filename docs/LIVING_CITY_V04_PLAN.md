# 霓港 v0.4 · 逐栋城市制作计划

本计划接续 v0.3，目标是让人从街道、入口、房间、居民和交通关系读懂城市生活。范围以可执行制作单元管理；建筑数、房间数、贴图数只记录覆盖面，不能代替画面与游玩验收。

## 基线与本轮边界

v0.3 已有南北两岸、北岸六区 48 个地址、每址 3 个公共楼层、电梯、4 条公共交通线路与 240 名逻辑居民。真实截图显示，入口、大堂中轴和家具组仍存在明显重复，住宅楼层从主通道看上去过于空旷；规则化路网、固定绕楼步行和重复地面材质削弱了城市生活感。

本轮保留既有可游玩坐标，细化 48 个外观、144 个公共楼层及其中的 576 个功能区，同时增加街道细节、立交与港口、居民行为和材质。功能区指同层房间、店铺或活动区域，不新增 576 个自然楼层。高层建筑仍只开放目录中的三个公共楼层，南岸背景建筑也不因本轮数量统计而视为全部开放。

## 制作单元与完成条件

每栋地址形成一张制作卡，卡内分别记录外观、三个公共层、入口路线、观察点和未开放内容。每个公共层的功能区需记录用途、主要家具、活动点、门洞、通路与采光方向。共享家具和材质允许复用，但空间顺序、服务对象和辨识物应服从这个地址。

| 阶段 | 工作 | 可核验证据 | 完成条件 |
| --- | --- | --- | --- |
| 设计 | 确定业态、主立面、入口、每层用途与视线 | 逐栋目录与设计数据 | 同类建筑仍有可描述的差异 |
| 空间 | 室外到入口、门厅到房间、房间到电梯 | 全址几何审计、代表用户操作 | 所有开放空间可进入并返回，家具不堵门 |
| 制作 | 轮廓、结构、家具、照明、标识、使用痕迹 | 已构建运行资产 | 细节不依赖说明文字才能被识别 |
| 材质 | 按实际尺度接入色彩、粗糙度与凹凸层次 | 平光与侧光实拍、来源记录 | 石、布、木、金属呈现不同响应，无整面塑料亮斑 |
| 视觉复核 | 从人眼高度和驾驶视角检查 | 每栋入口和公共层截图索引 | 标识不遮人、不穿插；用途、尺度和通路清楚 |
| 回归 | 出入、坐梯、旅行、保存、流式加载 | 单元规则和真实浏览器记录 | 无新异常，默认质量未被暗中调低 |

## 街道、港口与交通的连续关系

城市体验按真实路线验收：从住户入口走到街角服务点，经车站到商业区，再到码头跨海，进入目的建筑，乘电梯到公共层并返回街道。导览快速旅行可验证目的地落点，不能替代步行路线成立的证据。

| 工作包 | 制作目标 | 门槛与观察点 |
| --- | --- | --- |
| 街道 | 主干道、商业沿街、居民入口、港边步道呈现不同尺度 | 连续 200 米街行至少有可读转角、入口和街具；不以均匀放置小物体充数 |
| 立交 | 可开上的匝道、桥面、立柱、护栏与下层通行 | 路面支撑和视觉坡度一致；桥上不坠落；桥下不被上层地面吸附；出入口不封原道路 |
| 港口 | 候船、乘客步道、作业边界、仓库、岸吊和系泊关系 | 从街道能抵达候船处；船靠泊可正常上下；栏杆缺口仅位于真实通道 |
| 轻轨/地铁/高铁 | 站外导向、站厅、站台、等候与线路可辨识 | 四种交通分别真实候车、上车、运行、下车、出站；移动中不能落在无支撑处 |
| 公共观景 | 方向牌对应可见景物，栏杆有安全边界 | 接近边缘时不穿栏、相机不越墙；相邻建筑和海面是真实场景 |
| 居民 | 工作、购物、休息和对话围绕实际地点发生 | 活动锚点有人尺度，路径不穿实体；车辆附近能等待/避让；暂停后恢复无跳跃 |

## 视觉门槛

数量审计与视觉审查分开记录。每个画面采用产品内玩家可到达的位置；不得修改内部状态把角色放到不可达观察点。素材生成图只作为资产来源，验收画面须来自运行版本。

- **尺度**：人、门把手、桌椅、货柜和栏杆能互相校验；新增普通门净宽至少 0.9 米，主要公共通道保留 1.5 米以上，已有宽中轴也需要边缘内容解释其尺度。数值是游戏制作门槛，不宣称建筑法规认证。
- **材质**：石材、粉墙、木材、织物和金属在相同光照下能被分辨；粗糙表面不整体反光；织物不沿用石材色图；纹理不在拉长网格上被拉伸；远近镜头无明显接缝和闪烁。
- **建筑身份**：遮住标题后，至少从轮廓、入口、结构细节、业态物件中的两个维度辨认地址特点。简单换色或换名字不通过。
- **房间用途**：住宅能读出起居、就餐、睡眠、收纳；餐厅能读出用餐与备餐；医院能读出候诊与诊疗。新增分区不能只靠浮空牌说明用途。
- **生活痕迹**：海边盐渍、旧墙修补、店铺货品和住宅收纳应对应使用位置；随机噪声、到处污渍和完全相同的盆栽不作为完成依据。
- **灯光与构图**：入口不会被巨大出口牌遮住；电梯选择可读；室内有主体、背景和通路，沿主路看不到大面积无解释的空地；观景场所确实可见城市。

## 资源与流式加载门槛

保持默认高画质，加载按位置和方向触发，建筑碰撞与地面支持不依赖近景资源驻留。每次扩充都记录构建资源字节、驻留实例、绘制调用和首次可操作时间；设置明确上限后比较新增资产，不用变更画质掩盖预算失控。

自动检查至少覆盖一次北岸远距离往返，证明新资源真实请求、旧资源被释放、失败占位仍可识别、回到原址能恢复细节。材质采用共享纹理和实例批次；记录 GPU 资源释放计数，避免每次进室内新增且不回收。高层快速旅行、乘船保存和进入地图后恢复分别验证状态清理。

软件 GPU 只确认渲染和交互是否成立。真实帧率、显存和发热达标需要在注明型号的桌面与移动设备测量，未测不能写“高性能”或“全平台流畅”。

## 批次与发布顺序

1. **样板校正**：博物馆、茶楼、住宅、医院、最高塔、港口分别承担一种难题，先审查空间尺度与材质，再将共享做法展开。
2. **全址覆盖**：按六区推进外观、三层和分区；逐项留下未完成记录，不能用最后统一改色收尾。
3. **连续路线**：检查住区—商业—轨道—码头—两岸—高层的通行与状态转换。
4. **高质量复核**：48 个入口和 144 个楼层形成截图索引；逐栋人工视觉验收可以分批，但已检查与未检查必须明确区分。
5. **冻结与回归**：规则/几何、真实浏览器、资源摘要和默认高质量代表画面通过后，再提交发布；线上重新核对版本与实际入口。

本轮之外仍需独立制作的内容包括全部自然楼层、南岸室内、更多不规则街巷、角色骨骼与动作库、完整人车路权和城市服务玩法。只有这些场景具备可走可用的内容并经过证据验收，才逐步接近“完整真实城市”的目标。
