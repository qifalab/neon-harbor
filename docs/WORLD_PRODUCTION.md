# 霓港：美术与世界制作计划

## 成品方向

目标是有真实尺度、可游玩细节和明确地域气质的现代海滨城市。街景以石材、混凝土、玻璃、涂装金属和植物为基础；车身需要连续曲面和可信比例，人物需要自然的结构与动作。日落暖光与冷色海湾构成主色关系，霓虹主要服务夜间地标。方块堆叠、统一平涂和重复楼盒不能作为成品质量标准。

当前 v0.2 是代码生成资产和分块加载的改造阶段。它能验证驾驶、街景组合、光照和加载链路，但仍缺少专业制作的角色、完整动画、复杂车辆及高密度手工城区。将这些缺口写在计划中，不将程序化模型改良称为 AAA 资产生产完成。

## 画面验收标准

| 层次 | 制作要求 | 验证方式 |
| --- | --- | --- |
| 车辆 | 清晰侧影、连续车身曲面、真实轮距，玻璃/车漆/橡胶材质有区别；近看灯具、轮圈和内饰有结构 | 阳光下与背光驾驶画面；可见形体必须在物理包络内 |
| 人物 | 头身比例自然，肩/肘/膝可以分段运动，服装材质可区分；后续加入骨骼蒙皮与动作混合 | 步行、奔跑、转身和上下车视角；脚底与地面接触检查 |
| 街道 | 道路、路沿、铺地、橱窗入口与街道家具具有真实尺度；沿街可辨认功能 | 行人视角逐街检查，接近建筑和贴墙驾驶 |
| 建筑 | 轮廓、层高和立面节奏多样，近处门窗、檐棚和屋顶结构合理 | 至少三种时间与多个距离检查，立面不浮空、不交叉闪烁 |
| 光照 | 天空、雾、直射光、反射和曝光统一；阴影随场景稳定，昼夜变化不突兀 | 固定地点白天/日落/夜间画面，驾驶背景稳定性 |
| 世界连贯性 | 公园、商业街、码头和住宅区有连续道路与步行路线，转角不露出空洞 | 驾驶跨区录像、地图检查及碰撞审计 |

验收以真实游戏截图和交互为准。宣传图、离线生成图片和相机不可到达的摆拍不能代替游玩画面。

## 加载架构

常驻层保存道路、地表、碰撞、区域索引和简化远景。详细建筑与街景以有界街区资源存储，按当前位置和行驶方向异步请求；首屏等待周边资源就绪。加载成功后装配实例并替换对应远景，离开回收半径后释放实例缓冲和详细数据。失败时保留可识别远景、暴露重试入口，不使碰撞消失。

资源预算优先调整预取距离、缓存容量、并发请求和远景细节等级。默认近景质量保留，不用自动切换低画质来掩盖加载问题。用户仍可主动选择画质档位。

异步传输只解决资源何时到达。它不能单独解决 GPU 绘制、纹理显存、JavaScript 装配和纹理解码开销，因此生产架构还需要以下独立预算：

| 预算 | 当前检查 | 后续资产阶段 |
| --- | --- | --- |
| 下载与缓存 | 请求数量、已加载/失败/回收街区数、实际响应数据与缓存上限 | 压缩纹理与模型、内容哈希、离线缓存和带宽分级 |
| CPU | 固定物理步、空间索引、实例装配与主线程帧时间 | 分帧装配、Worker 解码、道路导航任务预算 |
| GPU | 共享材质、实例批量绘制、稳定阴影范围、远景替代 | 遮挡裁剪、网格细节等级、纹理显存预算和 GPU 计时 |
| 连续性 | 近区就绪、方向预取、卸载滞回、碰撞独立于资源驻留 | 根据实测车速与网络延迟动态调整预取范围 |

## 内容制作顺序

1. **本轮工程与画面改造**：驾驶、相机、碰撞、地表、曲面车辆、人物结构、天空反射、街景细节和街区加载。保持三项任务和存档流程，并通过真实浏览器测试。
2. **精修样板区**：逐个制作海滨商业街、车库及码头，不扩大地图面积；每个地点需兼顾步行和驾驶近看效果。建立素材命名、尺度、枢轴、材质槽、碰撞代理和许可证规范。
3. **正式资产管线**：接入原创或授权 glTF 资产、骨骼动画、压缩纹理与多级网格；加入自动模型尺度、材质和包体检查。程序化建筑继续用于布局和中远景，不承担全部近景精修。
4. **玩法深度**：完善交通路口、行人路径与回避；制作上下车动画、车辆改装、任务编辑器、可进入地点和可重复活动。每项玩法需要完整的失败、恢复和存档行为。
5. **按区扩展**：在样板区画面和真实设备帧时间达标后，按商业、住宅、工业与海岸主题扩建；每个区有独立地标、路线和任务，不能只复制楼体。
6. **多人制作**：独立房间权威模拟、客户端预测和校正、兴趣范围同步、账号持久化。基于实际同步量评估容量，单机静态 Pages 可以继续保留。

## 设备与发布门禁

持续集成覆盖数值回归、几何审计、实际 WebGL 交互、跨区加载和公开站点资源摘要。默认高画质的真实截图必须随版本留存；测试中主动使用低画质的情况要明确记录。

性能报告分别记录首次可操作时间、资源传输、驻留资源量、帧时间分位数和最长停顿。浏览器软件渲染只用于功能回归，不能推导用户显卡的 FPS。进入更大内容规模前，需要桌面集显、独显和移动设备的实际测量，再确定分辨率、远景与缓存预算。

发布流程为源码与资源生成 → 规则和世界测试 → 构建 → 浏览器驾驶/加载测试 → Pages 部署 → 公开地址版本与资源摘要核对 → 截图与报告归档。失败版本修复后重新运行门禁，不绕过检查发布。
