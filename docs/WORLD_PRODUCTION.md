# 霓港：美术与世界制作计划

更新日期：2026-10-04。当前三岸基础、验证与发布见 [v0.8 计划](REAL_CITY_V08_PLAN.md) 和 [QA_V08.md](QA_V08.md)。世界模拟器的整体分区与架构见 [WORLD_SIMULATOR_PLAN.md](WORLD_SIMULATOR_PLAN.md)，首个港湾样板的现场路线与门槛见 [HARBOR_SAMPLE_ACCEPTANCE.md](HARBOR_SAMPLE_ACCEPTANCE.md)。

## 成品方向

目标是有真实尺度、可游玩细节和明确地域气质的现代海滨城市。街景以石材、混凝土、玻璃、涂装金属和植物为基础；车身需要连续曲面和可信比例，人物需要自然的结构与动作。日落暖光与冷色海湾构成主色关系，霓虹主要服务夜间地标。方块堆叠、统一平涂和重复楼盒不能作为成品质量标准。

当前 v0.8 从公开 v0.7 重建三岸室内基础，并制作首个港湾生活样板。用户已选择先交付完整样板，再扩展整座城市：用双层巴士、经典双层小轮、双层街头电车及步行街坊生活建立可持续探索的路线，名称保持原创。GTA 与《赛博朋克》的资产、光照、动作和内容完成度用来检查差距，不据此宣称现有实现达到同等品质。

样板当前有三种原创曲面车船和实体楼梯、六家定制首层商铺、两套有来源的 CC0 扫描表面，以及 20 人、三店和货栈的有限日程与经济。完整游戏现场、至少 20 分钟连续路线和发布仍在核验，正式 GLB 资产生产、专业角色动画、真实硬件性能与完整全城尚未完成。基线功能通过、增加楼层或改材质参数都不能替代画面验收。

## 画面验收标准

| 层次 | 制作要求 | 验证方式 |
| --- | --- | --- |
| 车辆 | 清晰侧影、连续车身曲面、真实轮距，玻璃/车漆/橡胶材质有区别；近看灯具、轮圈和内饰有结构 | 阳光下与背光驾驶画面；可见形体必须在物理包络内 |
| 人物 | 头身比例自然，肩/肘/膝可以分段运动，服装材质可区分；后续加入骨骼蒙皮与动作混合 | 步行、奔跑、转身和上下车视角；脚底与地面接触检查 |
| 街道 | 道路、路沿、铺地、橱窗入口与街道家具具有真实尺度；沿街可辨认功能 | 行人视角逐街检查，接近建筑和贴墙驾驶 |
| 建筑 | 轮廓、层高和立面节奏多样，近处门窗、檐棚和屋顶结构合理 | 至少三种时间与多个距离检查，立面不浮空、不交叉闪烁 |
| 光照 | 天空、雾、直射光、反射和曝光统一；阴影随场景稳定，昼夜变化不突兀 | 固定地点白天/日落/夜间画面，驾驶背景稳定性 |
| 世界连贯性 | 公园、商业街、码头和住宅区有连续道路与步行路线，转角不露出空洞 | 驾驶跨区录像、地图检查及碰撞审计 |
| 室内 | 房门、楼板开洞、连续楼梯、电梯与家具能实际使用；首层业态与外观相符，通路没有穿插和阻挡 | 实际从街道入内、进房、上楼、乘梯、退出及重载；近看尺度和细部 |
| 生活 | 稳定身份的居民按实际路径通勤、到岗、购买、配送与返家；班次、钱与货来自明确状态 | 跟随居民、真实柜台交易、供应来源、缺货 / 缺钱、远处推进和存档一致性 |

验收以真实游戏截图和交互为准。宣传图、离线生成图片和相机不可到达的摆拍不能代替游玩画面。

## 加载架构

常驻层保存道路、地表、碰撞、区域索引和简化远景。详细建筑与街景以有界街区资源存储，按当前位置和行驶方向异步请求；首屏等待周边资源就绪。加载成功后装配实例并替换对应远景，离开回收半径后释放实例缓冲和详细数据。失败时保留可识别远景、暴露重试入口，不使碰撞消失。

资源预算优先调整预取距离、缓存容量、并发请求和远景细节等级。默认近景质量保留，不用自动切换低画质来掩盖加载问题。用户仍可主动选择画质档位。

v0.8 室内保留当前及相邻三个精细楼层；样板商铺近处 72 米内装配细部、离开 96 米后回收，扫描纹理在最后一个近景商铺卸载后释放。新交通有距离 LOD，近景人物最多 12 个完整实例，远处保留逻辑状态。这些机制仍需在完整路线中检查峰值与回收；不能由资源上限直接推导性能达标。

异步传输只解决资源何时到达。它不能单独解决 GPU 绘制、纹理显存、JavaScript 装配和纹理解码开销，因此生产架构还需要以下独立预算：

| 预算 | 当前检查 | 后续资产阶段 |
| --- | --- | --- |
| 下载与缓存 | 请求数量、已加载/失败/回收街区数、实际响应数据与缓存上限 | 压缩纹理与模型、内容哈希、离线缓存和带宽分级 |
| CPU | 固定物理步、空间索引、实例装配与主线程帧时间 | 分帧装配、Worker 解码、道路导航任务预算 |
| GPU | 共享材质、实例批量绘制、稳定阴影范围、远景替代 | 遮挡裁剪、网格细节等级、纹理显存预算和 GPU 计时 |
| 连续性 | 近区就绪、方向预取、卸载滞回、碰撞独立于资源驻留 | 根据实测车速与网络延迟动态调整预取范围 |

## 内容制作顺序

1. **三岸基础复核**：保留驾驶、相机、碰撞、地表、任务、地铁、渡轮、室内与私人房间功能。基线已有规则和真实浏览器证据，新样板接入后必须重跑受影响路线，不能继承旧版本全绿结论。
2. **港湾样板现场**：实际走住宅、商业街、三种双层交通与两岸室内，完成购物和货运再返回住宅。六店立面与房间、白天 / 日落 / 夜间和近处材质需逐图审查；至少 20 分钟连续路线保留等待和加载，禁止调试传送或改位置。现有代码与模块检查是这一阶段的进展，完整样板尚需验收。
3. **正式资产管线**：为关键近景接入原创或授权 GLB / glTF、骨骼动画、压缩纹理与多级网格，建立命名、尺度、枢轴、PBR、碰撞、LOD 与许可清单，以及自动资产和包体检查。现有程序化建筑继续服务布局与中远景，不能承担全部近景精修。
4. **生活与玩法深度**：先补新店员实际室内岗位、柜台服务和可使用物品，再扩充供应链、居民需求、动画与可重复活动。钱、货、工资和交易须有来源、失败与恢复行为；资源有限，不靠无限刷新制造活跃度。
5. **按区扩展**：样板画面与真实设备帧时通过后，按整体计划的六类城区逐区制作商业、住宅、工业、海岸与山地内容。每区保留独立地标、交通和生活证据，不只复制楼体；当前 220 地址目录不算全城制作完成。
6. **多人世界模拟**：现有最多 8 人的玩家、共用车辆与聊天服务继续保留。后续为新居民、班次、库存、交易和配送建立服务端权威、去重、兴趣同步及断线恢复；目前这些新状态仍是本地模拟，不能称为玩家共享经济。静态 Pages 继续承载默认单人客户端，多人后端另行部署。

## 设备与发布门禁

持续集成覆盖数值回归、几何审计、实际 WebGL 交互、跨区加载和公开站点资源摘要。默认高画质的真实截图必须随版本留存；测试中主动使用低画质的情况要明确记录。

性能报告分别记录首次可操作时间、资源传输、驻留资源量、帧时间分位数和最长停顿。浏览器软件渲染只用于功能回归，不能推导用户显卡的 FPS。进入更大内容规模前，需要桌面集显、独显和移动设备的实际测量，再确定分辨率、远景与缓存预算。

发布流程为源码与资源生成 → 规则和世界测试 → 构建 → 浏览器驾驶/加载测试 → Pages 部署 → 公开地址版本与资源摘要核对 → 截图与报告归档。失败版本修复后重新运行门禁，不绕过检查发布。
