# 霓港 Neon Harbor：网页版开放世界游戏计划

> 本文件保留 v0.1 的范围与验收历史。v0.2 的驾驶稳定性、世界几何重整及后续分阶段路线见 [工程计划](STABILITY_PLAN.md)。

## 项目目标与首版边界

在浏览器中完成「进入城市 → 徒步探索 → 驾车接单 → 完成任务 → 获得报酬 → 应对追捕 → 修车并继续探索」的可玩循环。项目借鉴开放世界城市游戏的交互方式，城市、角色、任务、美术与音效采用原创设计，不使用 GTA 的名称作为产品名，也不复制其地图、角色、剧情、商标、音乐或游戏文件。

首版 v0.1 交付一座紧凑的原创海滨城市、第三人称角色、可驾驶车辆、交通与警车、任务、成长存档和游戏界面。以可直接游玩、容易部署、便于继续开发为优先目标。GTA 5/6 的地图规模、剧情体量和制作规格需要长期团队开发，不属于这次首版的完成标准。

## 玩家体验

从主菜单进入海滨城市。道路、海岸、建筑街区、港口和任务地标为玩家提供定位。玩家可步行和驾驶，地图与任务面板提示当前目标；任务提供短周期目标，报酬用于呼叫维修或承担失败救援费用。发生交通碰撞或开火会提高警戒，脱离追捕后继续自由探索。高速行驶时需要先减速才能下车。

美术采用低多边形风格与鲜明的海岸配色。天空、雾、灯光及昼夜变化形成城市氛围。首先保证目标可读、车辆方向清楚、驾驶过程稳定，再增加装饰密度。触屏具有方向与动作按钮，桌面具有完整键盘操作；所有声音在用户交互后启动，并提供静音选项。

## 首版功能与验收

| 系统 | 首版内容 | 验收方式 |
| --- | --- | --- |
| 城市 | 海岸、水面、网格道路、六个命名区域、地标及碰撞边界 | 实际 WebGL 渲染，建筑与地图边界碰撞生效 |
| 角色 | 第三人称行走、冲刺、跳跃、视角跟随 | 连续输入可移动，碰撞后不会卡入障碍，暂停后停止模拟 |
| 驾驶 | 接近车辆交互、上下车、加速、转向、制动及车辆损伤 | 徒步到上车再下车的闭环可完成，碰撞反馈与状态一致 |
| 城市交通 | 沿固定路线运行的 10 辆交通车与基础碰撞响应 | 车辆持续运行；此版本不包含完整交通信号及复杂避让 AI |
| 警察 | 最高五星警戒、沿道路追击、视线与距离判定、逐级解除 | 触发后产生可见压力，逃离后可以解除，并能重新触发 |
| 基础战斗 | 向当前朝向射击、18 发弹匣、手动/自动装填、车辆损伤 | 开火消耗弹药，建筑阻挡射线，装填期间不可开火 |
| 任务 | 港湾速递、霓虹环线、幽灵信号三项限时驾驶任务 | 各有开始、目标、成功/失败与奖励；同时仅一项；首通奖励只发一次 |
| 经济与状态 | 现金、生命、体力、车辆状态、菜单呼叫维修和失败救援 | 收入与花费一致；资金不足有反馈；失败后能继续游戏 |
| 存档 | 本地进度与设置、JSON 进度导入/导出、确认后重置 | 刷新恢复现金、完成状态、最佳用时与位置；损坏或旧格式安全回退 |
| 导航与界面 | 小地图、任务目标、车辆/追捕状态、暂停设置 | 不同任务信息明确；菜单可返回游戏；窄屏仍可操作 |
| 触屏与音效 | 虚拟方向与动作按钮、程序生成音效、静音 | 指针释放后动作停止；音频错误不阻断游戏 |
| 部署与质量 | 静态构建、自动测试、GitHub Actions、可选手动 Pages | npm test、构建、真实浏览器测试通过，子路径资源正确 |

上述内容必须以实际实现和测试记录为依据。单元测试覆盖规则，浏览器测试覆盖真实 DOM、WebGL 初始化和主要交互；自动化无法替代完整的人类游玩体验评估。

### 当前首版的明确边界

存档恢复时重新初始化车辆、生命与弹药，并以步行状态继续；进行中的任务和追捕不保存。三项任务的首次奖励分别为 $850、$1,500、$2,000，重玩只更新最佳用时。维修通过菜单呼叫，每次 $150；「车库」尚未包含车辆所有权、收藏、改装或建筑内部。

行人为氛围动画，尚无对话或独立行为目标。战斗为朝向判定与车辆损伤，没有自由瞄准系统、人物受击动画或武器切换。城市使用固定道路和轻量碰撞，交通与警车的行为是首版实现，不代表完整城市 AI。仓库现已按所有者授权公开开源，单机版通过 Pages 手动部署。

## 技术结构

采用原生 ES Modules、Three.js 和静态页面。Three.js 0.185.1 随仓库分发，运行时无需访问外部 CDN。首版不依赖后端、注册账号或数据库，适合 GitHub Pages、Nginx 和其他静态托管。

| 层 | 职责 | 约束 |
| --- | --- | --- |
| 世界与渲染 | 场景生成、模型、材质、光照、相机、地图 | 与任务/奖励规则分离，低复用成本地增加街区 |
| 游戏规则 | 玩家和车辆状态、碰撞、交通、追捕、任务与经济 | 关键规则为可测试函数，避免依赖浏览器 DOM |
| 应用与输入 | 主循环、键盘/触控、菜单、HUD、存档 | 明确游戏/暂停状态，清理失焦时仍按下的输入 |
| 声音 | 用 Web Audio 合成引擎和提示音 | 用户手势后启用，可暂停、静音和恢复 |
| 工程工具 | 静态服务、构建、单元/端到端测试、CI | 不引入运行时构建服务；部署产物仅包含静态游戏 |

模拟采用固定 1/60 秒时间步，并对单帧间隔设置上限，避免切后台或卡顿后瞬间穿过地图。基础车辆和氛围角色采用固定数量，装饰使用简单几何体与重复材质；后续扩展需继续验证实体回收与长期运行资源占用。存档只保存必要状态并检查数据类型、范围与版本，任何本地存档都不作为未来联网模式的权威数据。

## 实施顺序与阶段产物

### 阶段一：可运行基础

建立仓库、许可证、页面入口、静态服务和构建；固定 Three.js 版本。实现菜单、加载失败提示、基本画面和可验证的游戏状态。产物是一份无需后端即可打开的应用，后续模块从同一入口集成。

### 阶段二：城市与移动

并行实现城市场景和角色/车辆规则，约定坐标、道路、障碍物与可交互点的数据接口。完成相机、碰撞、上下车和触屏输入。产物是可连续探索的城市，优先消除方向颠倒、穿模、失焦输入和卡车等基础问题。

### 阶段三：任务与风险回报

接入交通、警车和警戒规则。完成三种任务以及现金、状态、维修、救援和存档。任务规则在纯逻辑层验证，实际 UI 验证开始/完成/失败的状态一致。产物是一条可重复挑战、记录个人成绩的主循环；首版经济以有限的首通奖励为边界。

### 阶段四：呈现与可用性

统一视觉风格、HUD、小地图、目标反馈和菜单。加入昼夜与音效，校验桌面与触屏。检查使用中的页面，不用静态设计稿替代实际效果。保留质量设置以适应普通电脑和手机。

### 阶段五：验收与发布

运行全部单元测试、静态构建和真实浏览器用例，检查浏览器控制台、未处理异常与截图。对确认的问题完成修复后重新验证受影响路径。首版代码以 MIT 许可证公开，GitHub Pages 采用手动触发，发布前运行完整测试；保留其他静态托管说明。最终交付仓库、部署方式、已测内容及清晰的已知限制。

## 后续路线图（不计入首版完成项）

| 方向 | 可继续实现的内容 | 主要前提 |
| --- | --- | --- |
| 城市扩展 | 更多街区、桥梁、地形、远景与分区加载 | 性能基线、地图编辑与资产生产流程 |

| 剧情内容 | 原创人物、分支任务、过场和配音 | 剧本、资产许可与持续内容制作 |

| 成长与车辆 | 车库收藏、车辆差异、外观改装和更深入经济 | 先完成存档迁移及经济平衡设计 |

每轮后续开发都应形成新的范围、验收和性能预算，再进入实现；不会用“无限扩展”作为无法完成的本轮目标。
