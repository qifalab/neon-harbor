# 房间联机与发布方式（v0.8，始于 v0.7）

主站继续通过 GitHub Pages 发布单人默认客户端；仓库同时包含可运行的多人房间服务。客户端菜单里的“多人游玩”允许输入已部署服务的网址，建立房间或输入六位房间码加入。当前没有随主站上线的公网多人后端，需要自行运行或部署服务；主站可独立单人游玩。本文件保留原文件名供旧链接使用。

v0.8 将世界标识改为 `neon-harbor-v08`，容纳南岸与东湾室内。客户端与多人服务必须一起升级，使用相同世界版本；v0.7 的通过记录不能替代此次双浏览器回归。当前最终验收状态见 [QA_V08.md](QA_V08.md)。

## 运行

```sh
npm ci
npm run build
npm run start:multiplayer
```

打开 `http://127.0.0.1:5180`，选择“多人游玩”，服务地址填写同一网址。创建房间后，把房间码或邀请链接给另一浏览器。两人必须连接同一个房间服务，使用相同世界版本。

跨机器试玩时使用 `HOST=0.0.0.0 npm run start:multiplayer`。公开部署要在 HTTPS 反向代理后运行服务，允许长连接和即时刷新 SSE，关闭 `/api/events` 响应缓冲。`PORT` 设置监听端口；`NEON_ROOT` 设置静态客户端目录。

房间账本默认写入 `data/neon-harbor-room-economy.json`；可用 `NEON_ECONOMY_FILE=/path/rooms.json` 指定持久化文件。该文件保存房间商店库存、配送订单、20 名港湾样板居民的工资 / 购物余额与消费单位，服务重启后用同一房间码可继续。玩家身份没有账号系统，玩家个人钱包和随身物品仍以当前会话为边界。

客户端和服务分开部署时，通过 `NEON_ALLOWED_ORIGINS` 设置允许的客户端来源，逗号分隔，例如 `https://neon-harbor.qifalab.cd.mba`。默认只接受同源浏览器请求。GitHub Pages 的 HTTPS 客户端只能连接 HTTPS 服务。

也可构建容器：

```sh
docker build -f Dockerfile.multiplayer -t neon-harbor-rooms .
docker run --rm -p 5180:5180 -e NEON_ALLOWED_ORIGINS=https://neon-harbor.qifalab.cd.mba neon-harbor-rooms
```

## 当前能力

- 每房间最多 8 人，六位邀请房间码；不同房间互不混入。
- 步行、跳跃、驾车、城市导览、建筑和楼层里的真实位置同步；同一室内楼层可互见。
- 10 Hz 服务快照，远端人物与车辆插值；不同场景或大跨度旅行立即切换。
- 服务统一推进街道车流；共用车辆由服务仲裁占用，同一辆车不能同时由两人驾驶。
- 房间聊天、玩家列表、断线清理、车辆释放和离开后继续单人探索。
- 房间账本权威处理港湾商店购买、有限配送订单、玩家钱包与库存；购买请求使用幂等 `requestId`，重复提交不会重复扣款。
- 房间服务按共享游戏时钟每小时结算 20 名港湾样板居民工资，并在日常购物时从同一有限库存扣货；工资、购物、商店资金和消费单位进入同一有界交易记录。
- 无新增运行依赖；下行采用 SSE，上行采用有大小、频率、位置范围校验的 JSON 请求。
- v0.8 的位置边界为 X/Z 各 ±1,800 米，高度范围 −0.5 至 460 米；东湾高层属于允许的同步范围。边界校验不等同于逐面验证建筑碰撞或服务器物理模拟。

## 范围与限制

这是私人房间共同探索模式，尚未实现账号、数据库存档、跨服务器迁移、共同任务奖金、玩家战斗或完整的服务器物理反作弊。人物和已占用车辆的运动由驾驶者客户端计算，服务器校验位置范围、移动速度并独占仲裁车辆。城市导览允许显式旅行，因此并非严格防作弊竞技模式。

行人路径、动作、公共交通乘客与警察任务仍由各客户端运行；房间服务权威维护港湾样板的有限商店库存、配送订单、玩家钱包与购买 / 交付账本，并按同一房间时钟结算 20 名样板居民的工资和购物。每次购买、配送和居民交易都进入 `/api/economy` 返回的账本快照，SSE 会把同一房间的居民余额、库存、订单与交易记录广播给所有玩家。北岸 240 人网络、全城经济和公共交通乘客账本仍未统一为服务端状态，不能据此宣称全城共享经济。SSE 断开有短暂重连窗口，随后清理玩家与占车；配置 `NEON_ECONOMY_FILE` 后共享房间账本可跨服务重启恢复，玩家身份钱包不跨重启恢复。

房间快照里的玩家钱包和随身库存按会话分别返回；浏览器 `HarborLife` 的 `totalMoney`、`totalGoods` 与统计字段仍是本地展示账本，不能把多个玩家的个人库存相加后当成客户端聚合守恒。房间范围的库存、居民消费和交易守恒以服务端 `MultiplayerEconomy` 快照为准。

## 验证

`npm test` 包含实际 HTTP + SSE 的双客户端房间测试、房间容量/隔离、聊天、车辆独占和无效请求检查。`npx playwright test --config=playwright.multiplayer.config.js` 使用两个独立浏览器上下文操作可见菜单，检查互见的实际人物模型、步行同步、聊天和离开清理。v0.8 还需核对新世界标识、边界与东湾高层位置兼容；最终通过数量和证据链接统一填写在 [QA_V08.md](QA_V08.md)，未完成前保持待验证。

## v0.8 港湾生活的同步边界

双层巴士、电车、小轮的新增班次、居民路径和乘客登乘仍在各客户端运行；商店库存、有限配送订单、玩家钱包、20 名样板居民工资 / 购物与购买 / 交付记录由房间服务统一核算，且共享账本可跨重启恢复。房间同步玩家、可驾驶共用车辆、房间时间与聊天；北岸人口、全城经济、公共交通乘客账本和警察任务仍不是权威共享状态。公开 Pages 继续默认单人，仓库保留本地及内网房间服务。完整多人世界模拟阶段见 [制作计划](WORLD_SIMULATOR_PLAN.md)。
